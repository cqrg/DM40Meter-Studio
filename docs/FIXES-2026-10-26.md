## 一、修复：波形区永久空白（WebView2Loader 位宽不匹配）

### 现象

波形区**连坐标轴都不显示**（纯黑），但右侧测量统计正常累计样本、主读数正常刷新。

### 为什么统计正常而波形空白

两条路径分属不同层：

| 路径 | 依赖 | 结果 |
|---|---|---|
| 统计 / 读数 / 报警 / 录制 | `Dm40.Core`，纯托管代码 | 正常 |
| 波形 | `CoreWebView2.ExecuteScriptAsync`，需 WebView2 环境 | 失败 |

`MainWindow.InitWaveformWebView()` 里所有失败路径都是静默的：

```csharp
catch { /* WebView2 运行时缺失时静默，其余 UI 仍可用 */ }
// 以及
if (!e.IsSuccess) return;
```

所以异常被吞掉，界面上没有任何提示，而 `_webViewReady` 永远为 `false`，
`RefreshPlot()` 每次都在开头直接 `return`。

### 根因

加上日志后拿到真实异常：

```
System.BadImageFormatException: 试图加载格式不正确的程序 (HRESULT: 0x8007000B)
   在 Microsoft.Web.WebView2.Core.CoreWebView2Environment.CreateCoreWebView2EnvironmentWithOptions(...)
```

链路拆解：

1. `Dm40.App.csproj` 未声明 `PlatformTarget`，走 AnyCPU。
2. `Microsoft.Web.WebView2` 的 `build/Common.targets` 第 64 行：

   ```xml
   <EffectivePlatform Condition="'$(PlatformTarget)' == '' And '$(WebView2ProjectKind)' == 'managed'">x86</EffectivePlatform>
   ```

   于是 `EffectivePlatform = x86`，只复制 `runtimes/win-x86/native/WebView2Loader.dll`。

3. 而 .NET SDK 对 **AnyCPU 可执行文件**的 `Prefer32Bit` 默认是 `false`，
   实际进程以 **64 位**运行（已用 `IsWow64Process` 实测确认 `IsWow64=False`）。

4. 64 位进程 P/Invoke 32 位原生 DLL → `BadImageFormatException`。

### 为什么用 MSBuild.exe（VS）构建时不出现

旧式 WPF 工程在 Visual Studio 下默认 `Prefer32Bit=true`，进程是 32 位，
与 x86 loader 天然匹配。改用 `dotnet build` 才会暴露。

### 修复

`Directory.Build.targets`（新增文件，只对 `Dm40.App` 生效）：

```xml
<PropertyGroup Condition="'$(MSBuildProjectName)' == 'Dm40.App'">
  <Prefer32Bit>true</Prefer32Bit>
</PropertyGroup>
```

把进程钉成 32 位，与包自带的 x86 loader 对齐。

> 备选方案 `<PlatformTarget>x64</PlatformTarget>` 会与 .NET Framework 默认 RID
> `win7-x86` 冲突（`NETSDK1032`），除非同时改 `RuntimeIdentifier`，故未采用。

### 验证

修复后 `diag-webview.log`：

```
[init] InitializationCompleted IsSuccess=True
[nav]  NavigationCompleted IsSuccess=True
[probe] {"echarts":"object","cw":784,"ch":586,"hasDm40":"object"}
```

`echarts` 已加载、`#chart` 有非零尺寸、`window.dm40` 桥接就位，波形正常绘制。

### 附带

`MainWindow.xaml.cs` 的静默 `catch` 与 `!e.IsSuccess` 分支改为写
`diag-webview.log`（含 JS 侧探针）。**未改任何业务逻辑**，仅增加可观测性。

## 二、功能：切换测量档位时自动清零统计与波形

### 问题

切档后统计面板的 最小值/最大值/平均值/Δ 仍然带着上一档位的数据。
温度档的 30°C 会混进电压档 3.3V 的统计里 —— 不同量纲混算，结果没有意义。
波形同样保留旧档位的数据点，Y 轴被拉成两种量纲的跨度，新数据被压成一条平线。

### 改动

**`MeterSession.OnFrame`**：

```csharp
// 档位变化 → 先清零再累计
if (_lastKind != null && m.Kind != _lastKind)
{
    Statistics.Reset();
    Waveform.Clear();
    ModeChanged?.Invoke(m.Kind, _lastKind);
}
_lastKind = m.Kind;
```

判定依据是**设备回帧里的 `Kind` 变化**，而不是界面上按钮的回调。
这样三种来源都会被覆盖：GUI 点档位、CLI `send`、**用户在设备上手动拧旋钮**。

**`MainViewModel.OnModeChanged`**：清掉 UI 上的旧显示残留 ——
主读数置 `---`、单位与量程清空、副显置 `--`、统计面板通知刷新为
「样本 0 · 时长 00:00:00」，并丢弃待渲染的旧帧快照（`_latest = null`），
避免一次延迟刷新把旧值又贴回来。

波形无需额外处理：Core 清空后，下一个 33ms tick 发现 `Points.Length == 0`
即会向 ECharts 推空序列。

### 验证

- 编译通过，91 个既有单元测试全部通过（15 + 61 + 15）。
- ⚠️ 真机切档交互尚未完成自动化验证：界面上 10 个档位按钮是自绘控件，
  未暴露可驱动的 UI Automation pattern，无法脚本化点击。

## 三、构建补丁：无 Visual Studio 环境下编译 net48

`Directory.Build.props`（新增）：

```xml
<ItemGroup>
  <PackageReference Include="Microsoft.NETFramework.ReferenceAssemblies" Version="1.0.3" PrivateAssets="all" />
</ItemGroup>
```

机器上未安装 VS 时，`C:\Program Files (x86)\Reference Assemblies\...\.NETFramework\v4.8`
不存在，net48 目标无法解析引用程序集。该 NuGet 包（微软官方）补齐后，
`dotnet build` 即可直接构建全部 8 个项目，无需安装 Visual Studio。

### 运行单元测试

测试项目引用的是 `MSTest.TestAdapter/TestFramework 2.2.10`，但没有
`Microsoft.NET.Test.Sdk`，因此 `dotnet test` 会静默跳过并返回 0。改用：

```powershell
dotnet vstest tests\Dm40.Protocol.Tests\bin\Release\net48\Dm40.Protocol.Tests.dll
dotnet vstest tests\Dm40.Core.Tests\bin\Release\net48\Dm40.Core.Tests.dll
dotnet vstest tests\Dm40.Cli.Tests\bin\Release\net48\Dm40.Cli.Tests.dll
```

## 四、数据目录可重定向（便于统一归档）

原实现把录制文件写死到系统「文档」、截图写死到系统「图片」。
新增环境变量 `DM40_DATA_DIR`：设了就用它作为数据根目录，未设则回落系统「文档」。

```powershell
# 例：把所有录制/截图统一到 D 盘
$env:DM40_DATA_DIR = "D:\data\DM40"
```

截图目录仍可在「设置」里单独覆盖，优先级高于本默认值。

## 五、已发现但未修复的问题（供上游参考）

1. **CLI 退出码与契约不符**：`CLI_Contract.md` 规定连接失败应返回 `3`，
   但实测在「GATT 服务拿到 `notify=0 write=0`、一帧数据都没收到」的情况下，
   `stream` 仍返回 `0`。自动化若只看退出码会误判成功，需同时校验是否收到数据行。
2. **GUI 与 CLI 不能同时连接**：BLE 单连接独占。GUI 占用链路时跑 CLI，
   会拿到 `status=Connected` 但 `notify=0 write=0`。建议在 CLI 侧对此情况返回明确错误码。
3. **设置不持久化**：`SettingsWindow.OnSave` 只改内存中的 ViewModel，
   重启即回默认值（PRD §6.6.2 要求持久化到本地配置文件，尚未实现）。
4. **`scan` 偶发返回 2**：设备刚断开、尚未恢复广播时会扫不到，隔几秒重试即正常。
   非缺陷，但自动化场景需要注意。
